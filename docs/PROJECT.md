# Устройство проекта

## Структура

```text
dist/
  index.html          Страница и модальное окно
  styles.css          Оформление и мобильные размеры
  config.js           Данные салона
  products.js         Каталог и конструктор
  reviews.js          Подборка отзывов и источник
  app.js              Интерфейс, корзина, оформление
  order-adapter.js    Точка подключения сервера
  assets/
    mark.svg          Знак салона
    images/           Фотографии товаров
docs/PROJECT.md       Документация
PHOTO-SOURCES.md      Источники фотографий
start.cmd            Локальный запуск в Windows
vetka.code-workspace Настройки VS Code
```

Скрипты загружаются с `defer` по порядку: конфигурация, каталог, адаптер, отзывы, приложение. Настройки доступны через `window.SHOP`, `window.CATALOG`, `window.SHOP_REVIEWS`.

## Корзина и цены

Ключ localStorage: `flower-shop-cart-v1`. Для готового букета сохраняются идентификатор и количество. Для собственного букета сохраняются количества цветов, упаковка и открытка. После загрузки цена пересчитывается по текущему каталогу. Разные составы имеют разные ключи. Количество позиции ограничено 99.

Товары, цены и сумма в браузере не являются доверенными данными для сервера. Перед оформлением реальной заявки сервер должен заново проверить ассортимент, наличие, количество, стоимость и доставку.

## Подключение отправки

`orderAdapter.submit(order)` вызывается после проверки формы. Получает объект с `customer`, `items`, `subtotal`, `delivery` и `total`. Возвращает `{id, demo}`. В локальном режиме возвращается `demo: true`; в подключённой реализации возвращайте подтверждённый сервером идентификатор и `demo: false`.

`orderAdapter.feedback(answer)` получает `orderId`, `rating`, `comment`. Ошибки адаптеров отображаются в форме. При ошибке заказа корзина остаётся заполненной.

Для рабочего магазина необходимо:

1. Создать защищённый серверный обработчик с проверкой данных и защитой от повторных заявок.
2. Подключить доставку заявки владельцу или CRM и хранение заказов.
3. Подключить оплату отдельно, если она нужна.
4. Заменить контакты, ассортимент, фотографии и условия реальными.
5. Добавить необходимые уведомления об обработке данных и проверить получение заказа.

Ключи CRM, почты, платежей и мессенджеров храните только на сервере. Не помещайте их в config.js и GitHub.

## Отзывы

Тексты из reviews.js экранируются перед отображением. Ссылка принимается только с HTTPS-доменом 2ГИС. При некорректном источнике раздел скрывается. Отзывы не загружаются через внешние прокси; при смене магазина заменяйте подборку вручную.

## Проверка перед публикацией

Откройте сайт на компьютере и телефоне. Проверьте навигацию под закреплённой шапкой, изображения, цены и доставку. Добавьте готовый и собственный букет, измените количество и обновите страницу. Проверьте доставку и самовывоз. Подключённый сервер проверяйте отдельно на успешной заявке, ошибке и повторной отправке.

При установленном Node.js:

```powershell
node --check dist/app.js
node --check dist/config.js
node --check dist/products.js
node --check dist/reviews.js
node --check dist/order-adapter.js
```

## GitHub и обновления

В GitHub храните папку проекта с документацией и изображениями. Служебная папка Sites `.openai` и история её хранилища не нужны для самостоятельного проекта. Не переносите `.git` из чужого репозитория. Рабочей копией считайте папку, открытую в VS Code; копии сами не синхронизируются.
